# 通信优先，记录采用本地有界缓存

Q36 确认首版使用进程内有界缓存、后台批量记录和界面批量刷新。记录处理或磁盘持续落后时保持通信运行，队列溢出允许丢失记录并明确提示数量与时间范围；这种取舍避免记录阻塞改变被调试通信的行为，也要求回溯明确区分丢失和正常历史过期。

Redis 保留为实测后可选的异步记录后端，首版不依赖 Redis。回溯模块内部保留记录写入与存储实现的分离，协议和传输插件不依赖具体存储；不预先承诺无损高负载记录，也不引入无限队列。依据见 [缓存评估](../../.scratch/multi-protocol-debugger/recording-cache-options.md)。
