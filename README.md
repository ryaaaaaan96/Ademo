# 多协议调试工具

当前工作台支持多个独立会话标签页；主站支持 Modbus RTU 四区读取（01/02/03/04）、显式设备写入（05/06/0F/10）、多设备轮询及会话级读取重试；宿主提供串口会话生命周期和按操作、消息、时间查询及 CSV/JSONL 导出。Qt Widgets 的协议参数、操作和主站观测归 Modbus 插件，主体管理通道、记录与生命周期。当前范围以实施索引及各项验收证据为准。

## 构建与运行

复用 Windows x64、Qt 6.12.0 LLVM-MinGW、Clang 22.1.7、C++17、CMake 3.30.5 和 Ninja 1.12.1。不安装新工具或更改全局 PATH。

```powershell
./scripts/verify.ps1 -EvidenceId 08
./scripts/run.ps1
```

脚本运行 Debug/Release 配置、构建和 CTest，将日志、结果、截图和 SHA-256 写入指定 evidence 子目录。工具及临时 DLL 路径由 CMake 预设管理，构建产物不提交。Qt 自身为 release 构建，产品及 DLL 按相同 Debug/Release 配套编译。

界面输入串口参数、协议与角色，手动启动通信。默认串口 9600/8/even/1；RTU 采用 11 位字符，有校验需1停止位、无校验需2停止位。“运行中”表示端点打开；发送接纳、本地完成与设备确认分别记录。本地发送不能证明设备执行。停止或关闭释放端点；错误原因保留在概要和回溯。

## 主站读写与观测

四区动作 `read-coils/read-discrete/read-holding/read-input` 使用 `unit/start/count`；Unit 1..247，PDU 地址从0开始、范围0..65535，位数量1..2000、寄存器数量1..125，范围不得越界。成功结果为 `unit/area/function/start/values`；位值为JSON bool，寄存器为0..65535整数。表格按设备/区保留最近成功观测，失败不覆盖为伪造值。

设备写入动作 `write-single-coil/write-single-register/write-multiple-coils/write-multiple-registers` 使用 `unit/start` 和 `value`（单项）或 `values`（数组）。线圈为bool、寄存器为16位整数；非法输入不发送。写入只发送一次，超时/本地失败不自动重试，未确认显示结果不确定；人工重复形成新操作。广播交互当前明确拒绝，不能将无应答显示为设备确认。

## 会话读取重试与多设备轮询（05）

点击“会话读取重试与多设备轮询配置”打开配置对话框。默认额外读取重试2次、单次应答超时1000ms、重试间隔100ms。主面板选择设备、数据区及PDU范围后添加轮询，周期独立设置（10..3600000ms），从该任务上次结束计时。最多64项轮询；删除所有任务并应用可停止轮询。停止时保存配置、下次启动生效；运行中须等待当前及排队操作结束后应用。设备写入不能作为轮询动作。

公开 `SessionConfig.protocol` 字段为 `extraReadRetries`（0..10，默认2）、`responseTimeoutMs`（1..60000，默认1000）、`retryIntervalMs`（0..60000，默认100）、`polls`（数组）。每条任务为 `unit/action/start/count/intervalMs`，action为四种读取动作。运行中的 `configure-polling` 完整替换协议配置，失败保留旧配置。协议调度经宿主submit分配逻辑操作ID；手动和轮询共用最多64项等待队列，一条总线只允许一项在途。手动操作先于新轮询，轮询按到期任务轮转。

仅应答超时触发读取重试；CRC/长度错误保留原始记录并等到应答期限，协议异常、发送拒绝、本地失败与本地完成超时不自动重试。每次发送记录的metadata包含 `attempt/sendId`。传输send的ID是不透明令牌，旧令牌本地回调不能完成新尝试。逻辑操作ID保持不变，`retry-wait`为中间状态。

RTU无事务号。重试后有效读取响应可完成逻辑读取，但消息标记 `attempt=0/possibleAttempts`，结果含 `attemptAttributionUncertain=true`，不能证明属于最后尝试。全部尝试耗尽后隔离“应答超时+重试间隔”，再等帧间静默继续调度，单个设备不会永久阻塞其他轮询。有限隔离不能排除任意迟到；同设备/功能/数量后续候选响应标记 `freshnessUncertain=true`、消息operationId为0，经观察窗口可查，界面不将候选值写入最近成功观测。超时响应形状最多64项，超过后保守标记该运行全部读取归属不确定；重启清除运行状态。硬件环境与迟到上限仍需13验证。

## 插件、回溯与测试边界

SDK6在既有协议调度、配置、记录和从站准备能力上，增加通用本地状态与后台值任务，支持停止后保护未保存数据。宿主不解释Modbus字段。插件位于bin/plugins，配套SDK6、产品0.2、Qt完整版本、编译器、架构和构建配置，更新后重启；旧SDK DLL须重建。坏插件、身份重复和不兼容有诊断，其他功能可用。会话、视图与后台作业持有DLL租约，不支持热替换或插件崩溃隔离。

近期缓存、消息和操作均有可配置上限；缺失来源明确标记。概要可展开查询，CSV导出概要，JSONL保存实际可用原始字节、元数据与关联；后台导出不阻塞通信。ID在一个会话对象内不复用，运行代次过滤旧回调。

测试主要经DebugSession公开启停、submit、operation、traces、messages、trace和poll入口；底层注入可控传输及时间，使用实际协议DLL和原生Widgets。QSerialPort没有逐字节硬件间隙，ReceiveChunk.idleBeforeUs仅在后端确知时提供；主机分块延迟不冒充物理线路静默。真实串口失败路径与可控成功分开记录，模拟结果不构成硬件互通或时序保证；13等待独立对端与真实硬件条件。

## 从站外部 JSON 启动与四区应答（06）

在“从站文件与模拟数据”页为每个Unit选择外部JSON文件、添加并应用绑定，宿主选择slave角色后启动。一文件一设备，所有必需文件在后台完整校验后才打开串口；文件缺失、不可读或类型/范围错误时整个对应会话不启动，显示设备、路径与原因。不会用零值或内嵌数据兜底。文件格式和资源保护上限见 `.scratch/multi-protocol-debugger/slave-data-format.md` 及 `examples/slave-device.json`。

运行中可查看各设备独立四区模拟数据，应答功能码01/02/03/04和相应异常，广播读取与未知设备不应答。07补齐05/06/0F/10从站写响应，合法多值写入整体生效，再应答；广播写按每个设备独立范围执行且不应答。运行中的文件修改/删除不热加载，新启动重新读取。主站观测与从站模拟数据保持独立。被动应答与主站重试共用宿主发送令牌分配器，统一记录接纳、本地完成、失败或超时；不把本地完成当成对端收到。

## 从站运行编辑、导入与保存（08）

从站页可编辑单值、替换数据区范围和整份导入 JSON；完整校验后目标设备立即使用新数据，失败保留当前数据与绑定。导入成功绑定新文件，仍可继续编辑。保存/另存为在后台原子写入捕获快照，成功才更新绑定；保存期间的新修改仍为未保存。停止通信释放串口但保留本地数据，允许离线保存；重新加载和关闭前选择保存、放弃或取消。新启动仍必须读取并校验外部文件，保留数据不用于缺文件兜底。

文件操作不发送设备写入。每设备最多一个文件作业，全进程最多四项本地后台作业，超限明确拒绝；通信继续。公开动作、格式与路径往返规则见 `.scratch/multi-protocol-debugger/evidence/08/acceptance.md` 和 `slave-data-format.md`。

## 从站运行数据编辑与保存（08）

有效改值、整区范围替换和完整JSON导入立即作用于后续协议请求，文件保存独立执行；导入失败保留原数据与绑定。支持保存和另存为，后台捕获一致快照，期间的新修改仍为未保存。替换/重载前提供保存、放弃或取消；保存失败保留修改。停止后可继续编辑保存已加载从站数据，重新启动仍依赖外部文件。忙碌文件任务或取消选择会阻止关闭/重载，析构强制释放；配置替换先保护旧数据再撤下旧模型，防止旧保存覆盖新配置。

## 多会话与断线恢复（09）

“新增独立会话”创建另一个会话标签页，每页独立启停、通信、配置与记录。软件保护上限为16页；这不是已实测硬件容量承诺。规范化后相同COM端点互斥，合法端点可并行主从，某页断线不停止其他页。不同串口名是否接在同一物理总线须结合真实拓扑确认，同一RTU总线只能有一个主站；本次软件测试不证明实际接线拓扑。

页面顶部固定启停/重连/状态按钮，下方配置与协议内容可滚动。“按当前运行配置重连”保留当前协议运行实例；要应用新的端点设置，请停止并重新启动。可选择断线自动重连，以及重连后是否恢复轮询。默认不自动重连，恢复轮询默认开启，重连间隔默认1000ms（10..60000ms）。通用 `SessionConfig.recovery` 为 `autoReconnect/restorePolling/intervalMs`，不放入Modbus专用字段。

断线立即结束当前与排队通信操作，已提交而未确认的操作保留不确定提示；重连只恢复配置的轮询，不补发读写队列或未确认写入。关闭自动重连或停止会话会取消等待。恢复沿用同一协议实例与从站模拟数据，不调用启动文件准备、不重读外部JSON；停止再启动才重新校验文件，并保护未保存修改。连接代次隔离旧端点回调，协议运行租约独立保留后台文件任务及配置发布。回溯记录connection-lost/reconnect-request/connection-restored事件；RTU物理迟到响应继续遵循读取归属不确定规则。

公开宿主控制新增 `DebugSession.reconnect/configureRecovery/canReconnect`；工作台提供 `sessionCount/session/addSession/closeSession/sessionConfiguration/currentSessionIndex/selectSession`。关闭会话或窗口先检查未保存与忙碌状态，取消时保留模型、视图和其他会话。`sessionConfiguration(index)`读取尚未启动页面的当前端点/角色字段，供配置保存使用。验收见 `.scratch/multi-protocol-debugger/evidence/09/acceptance.md`。
