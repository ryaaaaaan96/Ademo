# 多协议调试工具

Windows Qt 工作台，当前正式流程覆盖 Modbus RTU 主站和从站。每个会话独立持有串口、配置、参数、通信记录和窗口；协议专属参数和操作留在插件。技术版本为产品 0.2 / SDK12。

## 本机启动与构建

已有 Release 构建时，双击根目录的 **[run-debugger.cmd](run-debugger.cmd)**。无需执行 PowerShell 脚本；缺少程序或运行库时会显示路径和提示。它启动本仓库 `build/qt-llvm-release/bin/multi_protocol_debugger.exe`，仅为该进程设置 Qt/LLVM DLL、Qt 插件和 QML 搜索路径。这是复用本机工具链的启动入口，不是便携发行包。

复用 Windows x64、Qt 6.12.0 LLVM-MinGW、Clang 22.1.7、C++17、CMake 3.30.5、Ninja 1.12.1。构建不安装新工具、不改全局 PATH。PowerShell 可直接运行下列可执行文件，不受 `.ps1` 执行策略限制：

```powershell
& C:/Qt/Tools/CMake_64/bin/cmake.exe --preset qt-llvm-release
& C:/Qt/Tools/CMake_64/bin/cmake.exe --build --preset qt-llvm-release --parallel 3
.\run-debugger.cmd
```

Debug 改用 `qt-llvm-debug`。原生测试串行运行，避免多个测试争抢窗口焦点：

```powershell
$env:PATH = 'C:/Qt/6.12.0/llvm-mingw_64/bin;C:/Qt/Tools/llvm-mingw2217_64/bin;' + $env:PATH
& C:/Qt/Tools/CMake_64/bin/ctest.exe --test-dir build/qt-llvm-debug --output-on-failure -j 1
```

[工具链核验记录](.scratch/multi-protocol-debugger/toolchain-environment.md)描述初始安装基线；当前产品构建、Qt/QML 与组合流程证据见 [UI13 验收](.scratch/multi-protocol-workbench-ui/evidence/UI13/acceptance.md)。Qt 自身是 release 库，产品与插件分别按同一 Debug/Release 配置配套编译。

## 创建会话和窗口

“新增独立会话”创建会话；“连接配置…”设置协议、角色、串口及重连策略，明确点击“启动会话”才打开端点。默认串口格式为 9600/8/even/1；RTU 采用 11 位字符，有校验使用 1 停止位，无校验使用 2 停止位。停止会话释放端点并保留运行数据和未提交内容。

左侧“会话与设备”定位目标。会话与绘图使用 QMainWindow 系统标题栏的最小化、最大化/还原和关闭按钮；浮动默认居中。拖动会话标题到工作台会出现停靠预览，松开后按预览方向平铺，也可用左右/上下平铺。最小化、切换页面、折叠记录不停止通信。

一个工作区最多保留 16 个会话配置（含关闭窗口），同一规范化串口互斥。窗口关闭只停止自己的会话并保留配置，从导航重开时保持停止。连接失败或断线不会停止其他会话；“连接配置…”中可选择自动重连及恢复轮询，重连不补发设备写入。实际总线只能有一个主站，软件隔离不代替物理拓扑检查。

## 主站参数读写和轮询

正式参数页是日常操作入口。没有参数时展开“参数来源与地址调试”，按设备地址、数据区、PDU 地址与数量添加参数，或选择参数定义 JSON 后明确加载应用。已有参数时该区域默认折叠。配置和文件应用不会自动通信。详细格式与旧地址行兼容见 [参数定义](docs/parameter-definition.md)。

选择当前设备和参数分组，使用行内“读取”、“读取选中项”或“读取当前组”。四区对应 01/02/03/04；设备地址 1..247，PDU 地址从 0 开始。表格保留最近成功观测；异常、不确定响应或读取失败不伪造当前值。窄窗口提供表格横向和内容纵向滚动。

双击线圈或保持寄存器的值会产生黄色待提交内容；只有行内“设置”发送 05/06 写入。离散输入和输入寄存器只读。设备确认才清除对应草稿，失败/不确定保留输入，迟到确认不清除新修改。需连续范围操作或 0F/10 批量写入时，打开“按功能码操作…”，明确设备、数据区/功能码、PDU 起址和 JSON 值后发送。打开此窗口不通信；未提交输入纳入关闭保护。所有写入均不自动重试，本地发送完成不能证明设备执行。

“开始轮询”捕获当前设备/组与所选范围及周期；切换设备、分组或文件页不改变采集目标。其他设备/组的任务保留。“停止会话轮询”仅停止后续轮询，不停止端点或取消已接受的在途操作。范围规划、队列容量和保护规则见 [参数读取与轮询](docs/parameter-polling.md)。

“读取重试配置…”独立设置额外读取重试（0..10，默认2）、单次应答超时（1..60000ms，默认1000）和重试间隔（0..60000ms，默认100），保留现有轮询范围及周期。运行时总线忙则拒绝应用并保留原配置。仅读取应答超时触发重试；协议异常、发送拒绝和本地失败不自动重试。RTU 无事务号，迟到或重试归属不确定的消息保留标记，不写成确定观测；真实硬件迟到上限仍待旧13验证。

## 文件、从站与曲线

每个会话有独立“文件编辑”页。新建、打开、编辑、保存、另存为与应用是独立动作；保存不会改变正在运行的参数，也不会发送设备写入。文件目标设备明确显示，切换设备先保护旧草稿。保存期间的新修改继续保留。主站参数文件、从站模拟文件及保护规则见 [文件编辑](docs/file-editor.md)。

从站在“连接配置…”选择 slave，通过从站参数页绑定设备 JSON 并启动。运行值修改明确提交到本地模拟数据，文件编辑另行保存/应用；其他设备和区域不受影响。停止后保留模拟数据供离线保存，重新启动仍校验外部文件。见 [从站参数工作流](docs/slave-parameter-workflow.md)及 [从站 JSON 格式](.scratch/multi-protocol-debugger/slave-data-format.md)。

选择数值寄存器后点击“绘制选中参数”打开真实 QML 曲线。曲线固定所属会话、设备及参数，改变当前设备不会串入其他值；暂停显示、图例、缩放、清空显示和窗口状态不停止采集。容量、缺失样本、实际负载边界见 [参数趋势](docs/parameter-trends.md)。

## 通信记录和工作区

每窗底部白底“通信记录”包含概要、回溯与导出、磁盘与历史。折叠不丢记录。查询和 CSV/JSONL 导出按所属会话、操作、消息和 UTC 定位；界面区分发送接纳、本地发送完成及协议确认。未知归属、正常过期、过载丢失与记录缺失分别呈现。磁盘记录必须主动开启，有界队列/保留上限及后台导出不阻塞通信；格式与容量见 [记录说明](.scratch/multi-protocol-debugger/recording-format.md)。

工作区保存配置、文件引用、当前设备、窗口开闭、浮动/停靠和位置。打开工作区后不自动通信；“恢复窗口布局”只调整当前窗口而不停止活动会话。待提交值、文件草稿和从站模拟数据有独立修改保护，多窗口确认后再次检查新修改。详见 [工作区与布局](docs/workspace-layout.md)。

## 插件和验证边界

SDK12 插件位于 `bin/plugins`，匹配 SDK、产品、Qt 完整版本、编译器、架构和构建配置。会话、界面、模态回调与后台作业持有 DLL 生命周期租约；更新后需重启，不支持热替换或崩溃隔离。宿主优先使用可选 `createParameterView`，未提供时仍回退 `createView`；Modbus 新流程不再展示临时兼容页。契约、降级与扩展测试见 [插件 UI 契约](docs/plugin-ui-extension.md)。

[综合实施索引](.scratch/multi-protocol-workbench-ui/implementation-plan.md)与各任务证据记录软件进度。UI01 原型确认不等同于正式产品操作确认；UI13 仍明确等待用户实际操作确认。旧13 真实硬件联调留待条件确认，旧14–19 不在本轮范围。
