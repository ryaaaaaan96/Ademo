Stage: 原型确认
Blocked by: 无

依据：[界面规格](../spec.md)、[综合实施索引](../implementation-plan.md)、[已批准拆分](../ticket-breakdown-draft.md)。复用已验收的旧 01–12 与 [Qt/LLVM-MinGW 工具链](../../multi-protocol-debugger/toolchain-environment.md)，不重做协议或传输基线。

## What to build

 修正原型显示问题，实际走通多窗口、参数操作、文件保存/应用和 QML 曲线，由用户确认布局和关键交互，留下可供正式实现参照的截图、流程及反馈。

- [x] 原型仅用模拟数据，不连接硬件；不把演示协议当成真实 UPP。
- [ ] 并排、浮动、记录随窗移动、单值列待提交状态、独立文件页和基础曲线均可操作。
- [ ] 明确记录用户接受与待改内容；编译或截图成功不能替代用户验收。
- [x] 不把原型的临时 JSON、行数/曲线数量限制或界面内业务逻辑直接复制进正式产品。

**覆盖新规格故事：** 71；用于提前验证其他故事的展示方向，不代替其产品实现验收。

- [ ] 用户明确确认本轮原型布局与关键交互，接受项和待改项记录到验收证据；在此之前不启动 UI02。

## 验证方式

复用独立 Qt 原型，使用模拟数据完成编译、真实 Widgets/QQuickWidget 操作检查及截图。记录用户实际反馈与明确确认；截图或编译成功不能代替用户验收。当前只推进原型，不接入正式产品通信，也不启动 UI02。

### 2026-10-23：审查修复并重新启动供操作

Spec 初审发现的新空从站保存越界已在 `3cf8ba8` 修复，实际按钮点击冒烟显示先添加设备且后续截图/QML继续完成。两轴独立复核后 Standards / Spec 均无剩余问题；既有产品 Debug CTest 11/11、238项通过。修正后的原型已通过 CMD 入口重新打开，窗口标题为“多协议调试工作台 · 界面原型（模拟数据）”。[审查与运行证据](../evidence/UI01/acceptance.md) 已保存；用户实际操作和确认仍未完成，不启动 UI02。

### 2026-10-23：采纳用户第一轮操作反馈

用户要求“通讯记录不要深色背景，也用白色，每个会话右上角加最小化和全屏”。已将记录改为白底深字，并增加会话最小化、全屏／还原按钮；最小化保留模拟通信与轮询，从左侧导航恢复，全屏可还原原停靠／浮窗状态。实际 Windows 按钮冒烟发现并修复导航树刷新导致的失效树项访问；复测 ExitCode=0、QQuickWidget Ready。新反馈版已启动，原实例和旧演示文件保留。见[本轮证据](../evidence/UI01/acceptance.md)。这次需求反馈不代表用户已接受修改后的界面，UI01 保持待确认，UI02 未启动。

### 2026-10-23：按用户澄清采用系统原生窗口

用户随后明确不要文字按钮，要正常独立窗口的三个按钮，并说明会话和绘图均使用 Qt 自带窗口类型。现将会话独立窗口与绘图统一为 QMainWindow，删除手工标题栏按钮，由系统提供最小化、最大化／还原与关闭；此次澄清取代上一版手工“全屏”按钮方案。会话仍可在独立窗口与停靠壳之间切换，复用同一内容与模拟运行数据；默认及新建会话以独立窗口展示。Windows 原生状态冒烟退出0，QQuickWidget Ready，两个审查轴均无剩余问题，详见[证据](../evidence/UI01/acceptance.md)。已启动供用户继续确认，UI02 未启动。

### 2026-10-23：保留拖动悬停平铺

用户要求保留浮窗拖到主窗口时的停靠／平铺交互。已为原生会话窗口补上拖动悬停预览，松开后按左／右／上／下停靠平铺；空工作台可落位，取消或拖出不落位，其他窗口遮挡工作台时拒绝落位。原生系统三按钮和白底通信记录保留。绘图窗口固定归属工作台，避免反复停靠连带重新挂载绘图，并由所属会话继续管理更新与销毁。Release 编译与完整原型冒烟退出0，两轴复核无剩余问题。回调冒烟不代替真实系统鼠标拖动／Esc 验收，待用户在已启动的新版中确认，UI02 未启动。[运行证据](../evidence/UI01/acceptance.md)。
