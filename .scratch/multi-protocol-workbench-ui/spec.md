# 多协议调试工作台：多窗口、参数表与插件界面变更规格

Status: ready-for-agent

发布日期：2026-10-23。依据本轮界面调整访谈 Q1–Q20 及用户确认的测试入口发布。本文为原产品规格的增量变更，不代表产品已经完成该变更，也不代表原型已经获得用户视觉与交互验收。

本规格优先规定调试窗口、参数展示、文件编辑和基础曲线行为；原规格中未被本文明确调整的通信、协议、插件加载、数据一致性及阶段约束继续有效。已完成的 RTU 实现优先复用。本次不重新发布实施任务，不改变既有任务的验收记录。

## Problem Statement

当前工具已实现多会话、Modbus RTU 主从站、读写与轮询、从站文件、回溯和工作区能力，但界面主要围绕连接配置、地址范围、功能码及 JSON 操作表单组织。操作人员需要反复填写调用参数，难以直接看到设备参数及其含义，也难以在一个工作台同时观察多个会话。

用户希望参考 QtIndustrialClient 的前端设计：围绕设备、参数分组、参数表和行内操作开展工作，文件编辑有独立页面。不同协议需要展示不同内容；没有名称的 Modbus 参数仍应通过寄存器地址直接调试。界面框架不能因增加一个协议或编辑页面就修改主体。

多个会话需要同时可见，窗口可以停靠或浮动，每个窗口的通信记录应跟随它移动。操作人员还需要查看参数趋势，并清楚区分最近观测值、待提交值、文件修改和已经应用的运行数据，避免误认为编辑或保存就已经改变了设备。

## Solution

提供以调试窗口为单位的 Qt Widgets 工作台。一个调试窗口对应一个调试会话，包含该会话的设备选择、参数分组、参数操作、文件编辑和底部通信记录。多个窗口可以在主界面并排、平铺，也可以拖出为独立窗口并放回，包括在不同显示器上查看。

左侧采用“会话→设备”导航，选择设备定位到所属调试窗口，不影响其他会话运行。会话配置通过独立入口完成，日常页面保留简明连接状态和必要控制。

框架提供可复用的参数表、窗口与页面承载、状态及记录基础能力；插件决定列、编辑控件、参数分组、操作和专用页面。默认参数表参考名称、类型、说明、值、单位、操作、更新时间等信息；有名称时显示名称，无名称时显示 Modbus 寄存器地址。采用单“值”列进行查看和编辑，以明确标记区分待提交内容。

每个调试窗口提供“参数操作／文件编辑”两页。文件编辑、保存、加载／应用和设备设置是独立动作。基础曲线采用 QWidget 内嵌 QML，通过参数入口打开，支持同一设备的多个数值参数、图例、暂停显示、清空和缩放。

完整主流程为：新建会话并配置协议、角色和端点 → 添加设备 → 加载参数 JSON 或由插件编辑页新建配置 → 启动通信 → 参数读写、轮询和曲线观察 → 按需编辑、保存及应用文件 → 关闭调试窗口停止对应会话。

## User Stories

1. 作为操作人员，我希望在同一工作台同时看到多个调试窗口，以便对比不同会话的数据。
2. 作为操作人员，我希望一个调试窗口对应一个会话，以便明确窗口中的操作作用于哪条连接。
3. 作为操作人员，我希望同一种协议可以拥有多个会话窗口，以便独立调试不同端点。
4. 作为操作人员，我希望不同协议的会话窗口可以同时显示，以便并行调试已有支持组合。
5. 作为操作人员，我希望在主窗口内并排或平铺调试窗口，以便利用桌面空间。
6. 作为操作人员，我希望把调试窗口拖出并移动到另一显示器，以便同时观察更多内容。

8. 作为操作人员，我希望通过“会话→设备”导航定位窗口和设备，以便快速切换观察对象。

## Implementation Decisions

1. **工作台与窗口。** 主体负责会话→设备导航、调试窗口容器、窗口布局和通用入口。一个调试窗口绑定一个会话实例，同协议的多个会话不能因协议身份相同而共享窗口状态。窗口内设备选择只改变展示上下文，不停止其他设备或会话。
2. **停靠和浮动。** 支持主窗口内平铺、独立浮动、跨显示器放置及重新停靠。通信记录属于调试窗口的内容，与参数及操作页面一起移动。工作区记录窗口位置、大小和停靠状态，提供恢复布局入口。具体 Qt 容器组合由实现验证，原型选用的控件不冻结为 SDK 契约。
3. **生命周期。** 窗口关闭与停止对应会话关联，保留会话配置以便重开；重开不自行恢复通信。最小化、折叠、移动、停靠及页面切换不等同于关闭。关闭或替换前处理未保存内容，取消操作应保留原会话与界面。延续已有停止、未确认写入和旧回调隔离语义。
4. **创建流程。** 新建会话选择已支持的协议、角色和端点，再添加该会话下的设备。设备加载参数 JSON 或进入插件编辑页创建配置。Modbus 主站支持按数据区、PDU 起始地址及数量生成参数行；没有具名文件不妨碍通用地址调试。从站启动仍要求全部必需数据文件有效。
5. **框架模板与插件。** 框架提供可复用表格、页面及状态基础能力，插件定义展示列、参数标识、编辑控件、权限、操作和分组，也可提供专用视图。框架不依协议名称增加字段或按钮分支，不把所有协议限制为寄存器。可在既有 SDK 边界增加必要的设备导航、选择上下文或视图能力，具体签名与版本升级按实现验证确定。
6. **表格基线。** 默认模板参考名称、类型、说明、值、单位、操作和更新时间；列并非所有插件必须实现的固定协议模型，允许插件增减显示内容。参数有名称时显示名称，Modbus 无名称时显示寄存器地址。不能把一段数值拼成概要字符串作为主要参数操作界面。主站观测值与从站模拟数据继续分离。
7. **参数分组。** 分组信息来自 JSON，由插件解释后提供给视图；不需要分组时全部进入默认组。主体不写死分组名或协议含义。文件字段和分组标识具体编码不是本次会话已经冻结的内容。
8. **单值列。** 主站平时显示最近读回结果，双击后编辑待提交值，点击行内设置才提交设备写入。待提交内容具有明确可见标记，界面和模型保留其与最近观测值的区别。轮询不得覆盖正在编辑的内容或待提交值；输入不能仅因本地发送或文件保存就被标为设备已确认。失败、超时或不确定结果继续可见。
9. **读取与轮询。** 提供行内读取、读取选中项、读取当前组以及开始／停止轮询入口。轮询范围与周期明确，已有会话级读取超时和重试配置继续有效。不同设备的轮询由已有协议调度管理；切换视图不改写轮询目标。设备设置不进入自动轮询或重试路径。
10. **角色操作。** 主站设置形成设备写入，遵循已确认的不自动重试规则。从站参数操作页修改的是本地模拟数据，校验后立即影响后续请求，保存负责持久化。两类操作在同一模板下由插件按角色提供，界面不能混淆本地修改、文件保存和实际设备写入。
11. **文件编辑页面。** 每个调试窗口有“参数操作／文件编辑”两页及独立编辑入口。编辑页显示目标设备和文件路径；切换设备不能让未完成的编辑静默改绑到另一设备。插件决定可编辑的参数、映射、命令或报文结构及其合法性，主体提供承载和通用基础能力。
12. **保存、应用与设置。** 文件保存／另存为只更新文件，不发送设备命令、不静默替换当前运行数据。用户明确执行加载／应用后，插件校验完整内容再更新指定目标；失败保留原数据。文件编辑草稿、已保存文件、当前运行内容和待提交设备值不能因复用一个“保存”动作而混同。正式文件版本、绑定及往返规则在既有文件能力上扩展，不直接采用原型的演示格式。
13. **从站文件一致性。** 保留外部数据文件启动依赖、缺失不启动、运行期间不热加载等规则。操作页的模拟值编辑即时生效；文件页的编辑经过保存及明确加载／应用后才影响当前运行数据。应用替换仍遵循完整校验、一条请求使用一致视图、失败保留旧值及未保存修改保护。文件保存与运行值保存需要明确来源，不能静默互相覆盖。
14. **协议编辑能力。** 不再把插件提供的协议编辑页面整体排除在外：插件可以在自身支持范围内提供编辑能力，框架只负责基础能力和挂载。不要求主体实现能编辑任意新协议的统一编辑器，也不要求所有插件都有相同编辑能力。新协议执行仍由插件实现；UPP 既定规范不可修改，未知线格式不得编造。
15. **曲线技术和基本行为。** 工作台和参数表继续采用 Qt Widgets，曲线通过 QQuickWidget 在 QWidget 中承载 QML。支持从参数入口打开曲线，在一个曲线窗口展示同一设备的多个数值参数，提供图例、暂停显示、清空及缩放。插件提供可绘制参数及数值语义；QML 不直接打开通道或实现协议交互。
16. **采集与显示分离。** 曲线观察已有参数更新，打开曲线不自动启动读取或轮询；持续采集由用户明确启用。暂停显示不停止通信，清空曲线不清空协议数据或原始记录。曲线数据归属于明确的会话、设备和参数，切换选择不能静默改变已有曲线的数据来源。正式采样容量、刷新预算及轴呈现通过实现和原型反馈确定，不从演示代码推导产品上限。
17. **通信记录。** 每个调试窗口底部显示所属会话的通信记录，支持概要和按需展开细节，继续使用统一记录、消息与操作关联能力。移动窗口不改变来源，解析失败或未识别设备的数据仍可回溯。既有容量限制、丢失提示、磁盘记录及导出语义保留，不为了多个窗口复制无限缓存。
18. **工作区与兼容。** 在现有工作区能力上保存会话、设备、配置文件引用和新的窗口布局，恢复后不自动通信。继续保留缺失插件的身份和无法解释的配置，修复后可恢复。已有配置、文件与插件兼容约束在变更时明确处理，不把原型格式当作正式迁移目标。
19. **复用与隔离。** 优先复用已验收的协议会话、端点占用、传输、轮询、读写、从站数据、回溯及文件服务。视图刷新和文件等待不阻塞通信；界面拥有关系变化不能使视图切换丢失必要观测状态、未保存保护或稳定的设备上下文。Qt 线程与对象生命周期规则延续现有基线。
20. **平台与交付边界。** 继续使用本机已确认的 Windows x64、Qt 6.12.0、LLVM-MinGW Clang 22.1.7、C++17、CMake、Ninja 和 VS Code，不重新选择工具链。先对已有 RTU 能力完成新界面与扩展边界验证；真实 UPP/CAN 和 Modbus TCP 继续遵守原产品阶段与资料依赖。
21. **原型与正式实现。** 原型用于确认布局、信息密度及操作流程，不替代协议、硬件或正式插件验证。正式实现依据本规格和后续确认的视觉反馈编写；不直接搬入原型的临时数据结构、模拟结果或 UI 内业务逻辑。原型中的布局排列只用于比较，不要求保留演示切换器。

## Testing Decisions

用户在本次 `to-spec` 发布过程中确认：**沿用调试会话公开接口和可控传输、时钟，并补充真实 Qt 界面的操作验收，覆盖窗口浮动／关闭、待提交值、文件保存与应用、QML 曲线。** 不新增一套绕开真实会话行为的测试框架。

- 主要行为测试继续从会话公开入口驱动，观察发送数据、操作结果、运行数据、文件内容、端点释放及回溯证据。
- 针对会话入口无法表达的窗口、编辑控件和 QML 行为，增加少量真实 Qt 界面流程验证。驱动实际控件或公开界面操作，观察可见状态及其对同一会话的影响，避免只验证模型后宣称界面可用。
- 测试不依赖私有控件层级、内部对象名约定、容器类型、辅助函数调用次序或精确像素；截图用于人工视觉验收，不替代行为断言。
- 文件测试使用隔离数据和明确的目标设备；模拟传输不访问真实硬件。真实串口和独立对端互通仍由原阶段验收承担。

| 验证范围 | 操作与可观察结果 |
| --- | --- |
| 多窗口与设备隔离 | 同时运行两个会话，在各窗口选择和操作设备，数据、写入目标、状态和记录均不串用；同协议多会话也能独立工作。 |
| 停靠与浮动 | 主窗口并排、拖出、放回、移动和折叠后，参数及记录仍属于同一会话，通信持续，窗口布局可保存恢复。跨显示器补充实际桌面检查。 |
| 关闭与重开 | 关闭只停止对应会话并释放其资源，其他会话继续；配置保留，重开不自动通信；取消未保存提示时保留原窗口与运行状态。 |
| 工作区恢复 | 会话、设备、文件引用和布局往返可用；恢复不触发通信；缺失插件配置不丢；无效工作区不覆盖当前有效配置。 |
| 参数模板与插件扩展 | 通过具有不同列、分组或编辑页面的最小配套插件验证主体不增加协议分支；插件专用内容正常挂载。该测试插件不冒充真实 UPP。 |
| 地址与分组 | 有名称、无名称、多个 JSON 分组及默认组均正确显示；Modbus 按地址范围生成参数后可读写对应目标；错误范围不形成错误操作。 |
| 单值列 | 在编辑中和已形成待提交值后注入新观测，输入均不被覆盖；待提交标记、最近结果及时间表达不把草稿冒充设备数据。 |
| 写入结果 | 仅点击设置才发送；成功、协议异常、超时、断线与停止的状态符合既有语义；写入不自动重试，也不因保存文件或打开曲线产生。 |
| 读取与轮询 | 行、选中项和组读取目标正确；范围与周期明确；切换分组、设备、页面和窗口不停止或改绑已有轮询；停止动作有效。 |
| 主从差异 | 主站编辑形成待提交值，从站操作页编辑立即改变模拟数据；模拟值与文件保存独立；仍可用控制输入验证后续从站应答。 |
| 文件编辑与应用 | 编辑、保存和另存为不改变当前运行内容、不发送写入；明确加载／应用才更新指定设备；打开另一个文件不隐式应用；失败保留旧数据。 |
| 文件与并发修改 | 保存失败、覆盖／重载取消、保存期间新修改及多会话关闭提示期间的新修改仍保留原有保护；不得因新视图绕开已有会话数据一致性行为。 |
| 从站启动依赖 | 文件不存在或无效时对应会话不启动，其他会话可用；外部改文件不热加载；重启按已确认规则读取文件。 |
| QML 曲线 | 实际 QQuickWidget 加载 QML，注入参数更新并观察对应曲线；同设备多参数可区分；图例、暂停显示、清空及缩放有效；打开曲线不增加通信请求。 |
| 采集与显示 | 暂停显示不停止轮询，切换设备不把另一设备的数据混入已有曲线，清空图形不删除记录或运行数据；刷新与容量受控，不拖住通信。 |
| 会话记录 | 各窗口记录随窗口移动且来源稳定；解析失败仍有证据；概要可定位到细节，既有丢失／过期表达及导出保持有效。 |
| 视觉与操作验收 | 用实际 Qt 程序完成创建、添加设备、并排／浮动、读写／轮询、文件保存／应用、曲线、关闭的完整流程；用户确认布局、可读性和操作目标清晰。 |

已有测试基础包括多会话隔离与关闭保护、轮询期间多设备观察、从站编辑／保存／重载取消、工作区往返及插件缺失恢复，以及读写、回溯和记录套件。复用这些行为基线，补充新界面交互的必要覆盖；不因既有软件验收通过就推定新界面已通过。

## Out of Scope

- 推倒已有协议和传输实现，或为了参考界面而把协议组帧、串口连接搬进主窗口或 QML。
- 全面切换 Qt Quick；本次 QML 用于已确认的基础曲线区域。
- 由主体实现面向任意协议的统一协议编辑器、通过任意 JSON 自动获得新协议执行能力或生成插件代码。
- 一次性交付所有协议的全部编辑功能；具体插件实现其已声明能力，UPP 不得修改既定规范或臆造线格式。
- 新增支持组合、跳过真实 UPP 资料依赖、提前实施 TCP，或以界面演示代替真实串口／CAN 联调。
- 写入自动重试、文件保存隐式设置设备、保存后自动热加载运行数据、打开曲线自动开始通信。
- 完整示波器、频谱分析、复杂绘图设计器、跨设备曲线关联及未经讨论的高级图形分析功能。
