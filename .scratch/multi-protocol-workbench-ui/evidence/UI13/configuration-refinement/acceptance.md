# 2026-10-24：参数配置界面收纳

根据用户截图反馈，将主站参数页的低频配置移至“配置…”窗口，主页面保留设备／分组、读取、绘图、轮询启停与摘要。文件编辑仍是独立页面。关闭配置窗口保留当前输入，打开／关闭不通信，参数添加／加载、轮询启动及读取重试应用仍为明确操作。实现保持在 Modbus 插件，宿主和协议逻辑未改。

## 验证

Qt 6.12.0 LLVM-MinGW，Debug/Release 增量全目标构建成功。新增实际 Qt 操作验收覆盖：默认收起配置、日常动作可见、重复打开、Escape 关闭、输入保留、不隐式改配置／通信，以及明确添加参数。已有参数定义、待提交写入、文件编辑和参数窗口测试迁移到新入口。

- 正常 Windows Debug 完整 CTest 首轮20/22：一项旧测试仍从主页面寻找“添加参数”，已更新为先进入配置并定向复验通过；另有窗口恢复问题仍失败。其余20套通过，包含新增UI验收、参数导入、文件保存应用、轮询、QML、读写及会话隔离。
- 正常 Windows Release 完整 CTest 21/22通过，仅窗口恢复失败。原始记录见 [Debug](debug-ctest.log)、[定向复验](debug-recheck.log)、[Release](release-ctest.log)。没有宣称完整回归全绿。
- 窗口恢复问题在修改前 Release 插件下同样复现，见[基线对照](layout-baseline-release.txt)，已单独记录[后续问题](../../../../window-screen-recovery/issues/01-offscreen-frame-restoration.md)。未将此失败作为本次配置窗口引入的回归。
- 初次沙箱运行遇到 Qt 文件保存及窗口套件超时，已终止并改为正常用户环境验证。新增测试首次错误地要求关闭会话销毁配置窗口，修正为项目原有“隐藏窗口并保留会话”的语义。基线对照第一次混用 Debug 测试与 Release 插件被配套指纹拒绝，随后使用一致 Release 完成有效对照；保留原始输出。
- Release 链接首次因旧实例占用插件失败，将旧 DLL 移至构建目录下独立备份后成功重新链接，未终止用户旧程序。
