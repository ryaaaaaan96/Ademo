### 用户澄清：采用系统原生 QMainWindow（2026-10-23）

用户明确“像正常独立窗口一样有三个按钮，不要显示文字”，随后说明会话和绘图均使用 Qt 默认提供按钮的窗口类型。因此上一节的手工文字按钮及全屏方案已被取代，旧截图06–08仅保留为历史证据。当前 SessionWindow 和 PlotWindow 均继承 QMainWindow，独立显示时使用 Qt::Window 系统标题栏，最小化、最大化／还原、关闭均由系统提供，不再手工绘制。SessionDock 仅作停靠壳；分离和停靠复用同一会话窗口与数据。默认和新建会话均以独立窗口展示，可通过菜单停靠，或在工作台平铺；通信记录保持白底。

同一 Qt/LLVM-MinGW Release 构建成功，Windows 原生 `--capture` 最终退出0，[QML结果](qmainwindow-capture-result.txt)为 Ready。冒烟验证会话与绘图窗口具备原生三个按钮标志；会话最小化／最大化期间模拟运行和轮询保持、左侧导航恢复、停靠恢复、最大化还原几何、会话关闭后停止并保留设备配置、重开保持停止且另一会话继续，以及绘图最小化／关闭不停止会话。两个独立代理最后复核 Standards 硬违规0、smell0，Spec剩余0。

已检查[会话客户区](09-qmainwindow-session-content.png)和[绘图客户区](10-qmainwindow-plot-content.png)，可读且内容正常。当前环境的屏幕帧抓取返回全黑，未将其作为有效证据提交；上述 QWidget::grab 只覆盖客户区，不包含系统标题栏，不能据此声称原生按钮视觉已由用户接受。原生按钮外观及鼠标操作继续由用户在已启动的新版原型中确认。上一轮反馈版窗口曾正常请求关闭，另有无主窗口的旧进程仍占用映像，保留旧映像并重新链接新文件，没有强制结束进程或覆盖用户演示数据。本轮仍只改独立原型，未重复正式产品测试，UI02 未启动。

### 保留拖动悬停停靠／平铺（2026-10-23）

用户要求保留此前浮窗拖到主窗口时的平铺能力。SessionWindow 原生 Windows 移动消息现在接入预览与落位逻辑；拖动悬停工作台显示落位预览，松开后按已有会话左／右／上／下平铺，空工作台也接收；移出、取消、源窗口隐藏／最小化及模态交互时不落位。实际 Z 序命中排除拖动源和透明预览后，只接受未被其他窗口遮挡的工作台；坐标按客户区比例转换为 Windows 物理像素。停靠操作排到原生移动消息退出后执行，避免在移动消息栈内重新挂载窗口。系统三按钮及白底记录保持。

同一 Qt/LLVM-MinGW Release 构建、Windows 原生完整 `--capture` 冒烟通过，退出0，[结果](drag-dock-capture-result.txt)。新增四向回调驱动断言验证预览、取消、主窗口外落位拒绝、四向几何关系；实际创建遮挡窗口验证预览和落位均拒绝；验证空工作台落位、运行／轮询／待提交值保持。之前的原生窗口状态、会话关闭重开、另一会话继续和绘图独立关闭检查继续运行。测试最初在右边界预览断言失败，定位为测试点落在工作台保留边距内，现测试点内移至有效区域，并将预览裁剪到有效区域。最终[平铺客户区截图](11-drag-docked-workbench.png)已目视检查。

中间版本反复切换会话父窗口曾产生 D3D11 swapchain 拒绝访问警告；绘图窗口的 Qt 父窗口现固定为工作台，由 SessionPane 保存 QPointer 并在销毁时删除存活绘图，避免随会话重新挂载。最终[Qt 原始日志](drag-dock-qt-messages.log)不再有 swapchain 警告，仅保留既有 QML palette 成员覆盖提示；QQuickWidget Ready，曲线客户区截图正常。两轴审查原遮挡 P2 已关闭，Standards 硬违规0、smell0，Spec剩余0，绘图生命周期修正也已独立复核。

这些检查调用实际预览／落位回调并使用真实 Windows Z 序，但没有自动执行系统标题栏鼠标拖动及 Esc 手势；这部分以及原生标题栏外观继续等待用户操作确认。新版已启动，旧实例／演示数据保留，构建产物不提交。本轮未修改正式产品，未重复旧 RTU 产品测试，UI02 未启动。
