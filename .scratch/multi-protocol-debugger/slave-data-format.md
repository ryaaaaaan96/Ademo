# RTU 从站数据文件格式 v1

一份外部 UTF-8 JSON 对应一个模拟设备。Unit ID 和文件路径由会话配置绑定，不在文件中重复保存。可从 [示例](../../examples/slave-device.json) 复制成每个设备独立的文件，再在插件的“从站文件与模拟数据”页逐个选择，添加并应用绑定。宿主选择 `slave` 角色后启动。

```json
{
  "version": 1,
  "areas": {
    "coils": { "start": 0, "values": [true, false] },
    "discrete": { "start": 0, "values": [false, true] },
    "holding": { "start": 0, "values": [10, 20] },
    "input": { "start": 0, "values": [100, 200] }
  }
}
```

`version` 必须为整数 1，四个数据区均必需。`start` 是从 0 开始的 PDU 地址，取 0..65535；`values` 表达该起址开始的连续范围。空数组表示空范围，不以零填充缺失区间。线圈与离散输入只接受 JSON 布尔值；寄存器只接受 0..65535 的 JSON 整数，不接受字符串、布尔或分数。每区最多 65536 点，起址加点数不得超过 65536。未知字段按原 JSON 对象保留，不参与当前协议解释；不对未知版本降级猜测。

会话配置使用 `protocol.devices: [{"unit":17,"path":"C:/data/device17.json"}]`，Unit 是唯一的 1..247 整数；每个设备绑定不同的规范化文件路径。启动 API 要求绝对路径；工作区恢复时由工作区层相对其目录解析文件引用，不能相对进程当前目录猜测。

当前软件边界为每会话 1..32 个设备、单文件最多 4 MiB、全部文件最多 16 MiB；后台准备全进程最多保留 4 个任务，繁忙时明确拒绝新准备。限制包含等待完成但已取消的任务，避免反复启停造成无限排队。这些为资源保护上限，不代表已验证目标硬件持续容量。

从站启动在后台依次读取并校验全部文件。任一文件不存在、不可读、JSON/类型/范围无效时，整个会话不打开端点，并提示 Unit、路径与原因；不以缓存、内嵌快照或零值兜底。停止/销毁使准备结果失效，但安全保留后台任务及插件租约直到完成，其他会话可继续。

运行中只使用已经验证的数据，外部文件修改或删除不热加载；停止后再次启动重新读取全部文件。从站只对配置的设备应答，01/02/03/04 采用对应数据区，越界返回 02、非法数量返回 03、未支持功能返回 01，CRC/可信帧内间隙错误、未知设备与广播读取不应答。请求及被动应答经统一通道记录，响应源区间可查；应答本地完成、失败、拒绝或 1 秒本地超时分别可见，发送失败不自动重发。

公共查询 `DebugSession.snapshot()`（插件通过 `SessionAccess.snapshot`）返回 `role: "slave"` 与 `devices` 数组，每项含 `unit`、绝对 `path`、完整 `data` 文档、`dirty` 和十进制字符串 `revision`。主站观测值与从站模拟数据使用独立界面与模型。本项 06 不提供运行编辑、导入或保存，分别留待 07/08；无需修改文件即可查看当前模拟数据。

实际 QSerialPort 只提供主机字节块，没有可信线路 t1.5 时间；内核保守保留不完整请求，候选请求完整后等待主机观测静默，不把主机分块延迟当作物理间隙。可信 `idleBeforeUs` 才用于物理间隙判断。真实串口时序与独立对端互通仍由 13 验收。
