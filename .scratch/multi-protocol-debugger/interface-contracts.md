# 多协议调试工具接口契约草案

Status: needs-triage

产品行为以 [正式规格](spec.md) 为准。开发使用 VS Code + CMake，Qt 6.12.0 / LLVM-MinGW Clang 22.1.7 / C++17 已完成 [环境核验](toolchain-environment.md)；本草案仍不代表已发布 SDK。

依据：2026-10-22 经 Q36 确认的 [架构基线](architecture.md)与 [术语](../../GLOSSARY.md)。产品行为沿用已确认结论；下文类型名和方法形状是实施提案，尚未作为可编译 SDK 或固定 ABI 发布。已验证工具链直接复用；[issue 01](issues/01-rtu-session-lifecycle.md) 在会话启停流程中验证插件接口，[issue 02](issues/02-rtu-first-register-read.md) 在首次读取流程中选择 Modbus 实现。当前编号按新发布的 19 项索引解释。

## 模块与可替换位置

采用小 Interface 承载完整行为的 Module。协议交互的 Seam 位于协议会话，传输的 Seam 位于通道，记录存储的 Seam 位于回溯模块内部。RTU/CAN/TCP 是不同传输 Adapter；Modbus/UPP 是不同协议 Adapter。宿主不按协议名字判断功能，不把每个编解码步骤暴露给调用者。

| Module | Interface 的调用者与能力 | Implementation 隐藏的内容 |
| --- | --- | --- |
| 插件宿主 | 工作台查询可用能力、创建和销毁会话 | 文件发现、兼容校验、工厂、插件对象存活 |
| 会话宿主 | 工作台启动、停止、提交操作和订阅概要 | 配置校验、端点占用、运行代次、模块连接 |
| 协议会话 | 宿主提交操作及输入事件，接收消息与结果 | 组帧、解析、轮询、应答关联、读取重试、从站模拟数据 |
| 通道 | 协议会话异步收发、宿主启停端点 | 后端 I/O、部分写入、连接身份、有限发送队列 |
| 回溯 | 通道/协议提交记录，工作台查询与导出 | 近期缓存、异步落盘、索引、轮换、丢失统计 |
| 协议视图 | 工作台创建 QWidget 容器 | 协议专用编辑、配置和数据显示；后续可包含 QML |

首版不发布通用存储插件协议，不要求每个协议都拆出相同 Codec 子类。协议 Implementation 可以在内部复用编解码库，外部通过协议会话使用其完整交互能力。

## 公共数据契约

| 概念类型 | 必须表达的内容 | 不变量 |
| --- | --- | --- |
| `PluginDescriptor` | 稳定 ID、插件版本、SDK/构建兼容声明、角色、支持组合、配置/操作/视图能力 | 描述来自插件；版本不兼容不创建实例；相同 ID 冲突明确报错 |
| `SessionConfig` | 协议/传输 ID、角色、端点参数、设备集合、会话通信参数、插件配置 | 一个端点、一种协议；设备键由协议解释 |
| `ConnectionKey` | 会话运行代次、端点内连接 ID、连接代次 | 重启/重连后旧输入不归入新操作；TCP 阶段逐连接隔离解析 |
| `TransportUnit` | 原始字节、流块/帧/数据报种类、连接键、观测时间、传输元数据 | 不把读取块等同于协议报文；元数据保留后端实际能力 |
| `SendRequest` | 发送 ID、连接目标、字节和必要元数据 | 协议提供 CAN 等必要寻址；不支持的组合或字段明确拒绝 |
| `TraceRecord` / `TraceRef` | 记录 ID、方向、时间、原始单元或状态、可选字节区间 | 记录 ID 不复用；缓存淘汰或记录丢失后引用仍可解释 |
| `Message` | 协议类型/设备键、字段树、解析结果、来源引用集合 | 不含 CAN 专用字段；来源允许多对多关联 |
| `OperationRequest` | 操作 ID、动作 ID、目标设备、插件定义的参数 | 宿主分配操作 ID；由插件验证动作语义，不接受调用者自行声明“这是可重试读取” |
| `OperationUpdate` | 操作 ID、结果/进展、发送尝试和消息关联、可读错误 | 本地发送完成不等于设备执行成功；手动重发写入使用新操作 ID |
| `Diagnostic` | 稳定错误类别、可读原因、相关插件/会话/设备/路径/记录引用 | 概要适合操作人员，细节可回溯；后台错误不要求复杂界面状态 |

时间区分主机墙上时间、用于超时的单调时间和可选硬件时间，不虚构后端时间精度。CAN 元数据保留 ID、帧格式及实际支持的标志；TCP 对端与串口参数也按各自语义提供，不能默默丢弃必要字段。

## 插件发现与创建

工厂形状提案：`ProtocolPlugin.describe()`、`createSession(context)`、可选 `createView(viewContext, parent)`；`TransportPlugin.describe()`、`createEndpoint(config, context)`。工厂返回的对象由宿主管理生命周期，销毁方式由 SDK 统一声明。

`context` 只提供通道访问、计时、记录和结果发布等必要能力，不暴露工作台内部对象。配置描述、操作定义与可选专用视图均由插件提供；默认表单只解释通用字段描述，寄存器逻辑留在 Modbus 插件。

宿主检查支持组合和编译兼容声明后才创建对象。缺失、不兼容或加载失败时保留原始插件配置并禁用相关会话，其他会话可继续运行。首版按配套构建交付；Qt/编译器/C++ 版本已按本机环境固定，项目插件兼容标记与 ABI 由 issue 01 验证。

## 会话与协议的 Interface

以下为概念调用顺序，异步结果以请求身份和运行代次关联；不是要求调用者等待同步文件或 I/O 操作。

| 调用 | 输入 | 完成或输出 |
| --- | --- | --- |
| `prepare` | 启动请求、配置快照 | 就绪或诊断；校验所有必需数据文件和支持组合 |
| `activate` | 已打开的通道能力、运行代次 | 开始接收/响应，主站可开始已配置的轮询 |
| `submit` | `OperationRequest` | 操作接受或拒绝，随后产生结果/记录关联 |
| `onInput` | 接收单元、连接变化、发送结果或计时事件 | 消息、诊断、发送意图和操作更新 |
| `stop` | 停止原因、运行代次 | 取消计时/轮询、结束未完成操作，通知宿主停止完成 |

准备阶段可以异步读取文件，但不能先对外通信再报告某个必需 JSON 无效。宿主在准备成功后申请端点并打开通道；后端在协议尚未激活时不丢失连接建立后的首批输入。配置在准备过程中被更换时丢弃旧准备结果，避免旧文件数据覆盖新选择。

协议会话决定一项操作是否只读、是否应答及何时完成。读取使用会话配置：额外重试默认 2 次、单次应答超时 1000 ms、间隔 100 ms，均可修改，0 次关闭重试。设备写入/参数设置不能自动重复提交；传输内部完成一次发送的部分写入不算新操作重试。

正常响应、协议异常、超时和传输失败分别保留。具体可重试错误由协议明确定义；不把所有异常一律重试，不对未知 UPP 指令猜测读写属性。轮询周期与重试间隔独立；RTU 按一个总线调度在途事务，迟到或无法可靠归属的输入仍记录，不强行关联。

断线结束当前未完成操作；可选重连只恢复连接与已有轮询，不补发写入。停止后重启会话重新加载外部 JSON；同一运行会话内的连接重建不触发文件自动重载。

## 通道 Interface

形状提案为 `open(request)`、`send(SendRequest)`、`close(request)`，输出打开结果、原始输入、发送结果与连接事件。发送提交可立即返回“接受/拒绝”；被接受后必须产生且仅产生一次最终本地发送结果，必要时伴随部分进展。队列满时明确拒绝，不无限积压。

通道只知道传输，不解析 Modbus/UPP。部分写入、后端错误及连接代次由通道维护；协议经统一入口发送，不能绕过记录直接打开串口或 socket。通信数据进入统一记录入口并获得来源身份后再交给协议解析，记录过载不阻止协议接收数据。

计时依赖由宿主注入，协议决定何时请求超时事件。串口后端报告实际可获得的接收活动时间与错误；RTU 的组帧和等待规则归协议。Windows 串口时间精度必须在实际实现中验证，不用每次读取一块数据代替完整的 RTU 成帧规则。

未发送、已提交但未确认和后端报告失败有不同含义；取消或关闭不能撤回已经交给后端的字节。对关闭后到达的回调检查代次，避免旧结果修改新会话。

## 记录与查询 Interface

写入 Interface 提案为 `append(record)`，查询为分页的 `query(filter, cursor)`、关联查询 `resolve(refs)` 和后台 `export(request)`。记录写入不等待磁盘；接受进入缓存/队列不等于已经持久化。

近期缓存和后台写入队列均有上限，磁盘记录由用户开启。发生溢出时保留独立的丢失计数与范围，不能让丢失提示也只能排在已满队列里。来源查询区分可用、正常过期和记录丢失；概要与 Message 不伪造缺少的原始字节。

CSV 导出概要，JSONL 导出所选范围内实际可用的原始字节、元数据与关联，标注缺失来源。导出不阻塞通信，导出期间被轮换的数据必须通过快照/保留引用或明确缺失结果处理，不能静默省略。

内部记录写入器接本地文件；未来 Redis Adapter 可从该位置替换或补充实现，不把 Redis 连接暴露给协议或 GUI。队列、缓存和磁盘保留上限分别配置，容量与吞吐结果由 issue 13 测量。

## 从站数据与工作区

Modbus 插件持有数据区和数值。工作区持有设备与外部 JSON 文件的绑定，JSON 仍是一文件一从站。文件结构可扩展；格式版本、路径规则和未知字段保存规则在 issue 06/08/10 中写清，不在主体增加 Modbus 字段解析。

启动一次读取并校验该会话所有必需文件；任一缺失、不可读或无效时整个会话不启动。运行中外部文件变化不热加载。有效的编辑/导入在一次请求结束与下一次请求开始之间应用，失败保留旧数据与旧文件绑定。

编辑更新运行数据，保存负责写文件。文件读取、解析和写入在合适执行上下文中完成，协议执行上下文只进行已校验数据的切换。保存捕获一致快照；写文件期间的新修改仍算未保存，保存失败不能错误清除修改状态。未保存修改的替换沿用保存/放弃/取消提示。

实现提案：有效导入后绑定所导入的文件，保存写回当前绑定，另存为成功后绑定新文件；相对路径以工作区目录为基准。原文件与工作区引用只有在对应操作成功后才更新。这些规则随 issue 06/08/10 做往返验证，字段名仍可调整。

## 线程、所有权和停止

- QWidget/QQuickWidget 与 GUI 模型由 GUI 线程管理；协议和通道状态在各自所属执行上下文中串行访问，跨上下文传递值或有明确生命周期的不可变数据。
- 协议实例获得宿主提供的计时和通道接口。宿主拥有会话/端点生命周期；插件对象持有期间其代码保持加载，首版不运行中卸载插件。
- 停止时先拒绝新操作并取消轮询/计时，再关闭通道、结束未完成操作、释放端点占用。停止完成只代表该会话不再处理遗留任务，不代表未确认写入未执行。
- 停止后的会话可留在界面继续编辑配置。销毁时先撤下视图和调用入口，完成停止并断开回调，再按创建契约销毁协议/通道对象；最后才允许在应用退出时释放插件。
- 不预设每会话一个线程。具体线程数按测量选择；磁盘等待和逐条界面刷新不进入通信关键路径。

## 验证和开放项

用户已确认以调试会话的公开控制与查询接口作为主要测试入口，从启动/停止、读写、导入和编辑观察操作结果、发送数据及回溯记录；底层注入可控传输和时钟。以外部行为覆盖请求顺序、超时、关闭和错误，不窥视私有队列。插件加载及必要界面流程另作少量边界验证；实际串口、独立 Modbus 对端及 CAN 硬件验证补充真实时序证据。

开放项由当前 issue 承接：01 在会话启停中验证插件 ABI/对象销毁；02 在首次读取中选择可注入 I/O 的 Modbus 实现；06/08/10 完善文件格式和引用规则；13 验证 RTU 时序、负载与容量；14/15 核对 UPP 固定规范与 CAN 硬件并实现真实交互。工具链已验证；当前没有 UPP 字段、性能保证或已编译 SDK 的结论。
