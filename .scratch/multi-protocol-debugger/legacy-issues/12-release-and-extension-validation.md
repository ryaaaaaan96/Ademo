# 12 完成插件扩展验收与 Windows 交付验证

Status: needs-triage
Stage: 最终验收
Dependencies: 08、10、11

## 目标

验证整体支持列表和插件扩展承诺，提供可安装运行的 Windows x64 交付物及清楚的能力限制。依据：[设计规格](../spec.md)、[架构](../architecture.md)、[实施索引](../implementation-plan.md)。

## 工作范围

- 核对 RTU/TCP 主从、UPP/CAN 真实示例、多会话、工作区与记录功能的验证覆盖。
- 在配套构建环境与清洁 Windows 环境验证插件发现、Qt/驱动部署和必要运行依赖。
- 验证移除/换错插件后的可用功能、配置保留与修复重启路径，以及缺外部 JSON 时的启动提示。
- 以真实 UPP 接入变更检查主体稳定性，发布新增协议/传输插件的最小开发说明。

## 验收条件

- [ ] 支持列表中的每项有独立验证证据，未覆盖硬件/速率明确列出。
- [ ] 新协议/传输的接入通过已发布 Interface，主体不依赖协议名称或寄存器假设。
- [ ] 多种会话并行、停止重启、过载记录及导出符合基线；不宣称记录永不丢失。
- [ ] 缺插件和缺 JSON 的恢复路径可由操作人员完成，配置不会被保存操作清除。
- [ ] 交付说明列出确切构建版本、驱动/文件需求、已测容量与已知限制；运行不依赖 Redis。
- [ ] 更新接口、用户说明与 issue 中的验证结果；产品代码和二进制实际存在后才标记相应交付完成。
