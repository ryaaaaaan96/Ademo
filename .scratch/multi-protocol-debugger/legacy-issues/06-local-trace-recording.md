# 06 实现本地回溯、导出和通信优先的过载处理

Status: needs-triage
Stage: RTU
Dependencies: 02、03

## 目标

关联原始记录、协议消息和调试操作，提供有界近期缓存、可选磁盘记录与导出，记录过载时保持通信。依据：[接口契约](../interface-contracts.md)、[ADR 0005](../../../docs/adr/0005-separate-traces-messages-and-operations.md)、[ADR 0009](../../../docs/adr/0009-communication-first-bounded-recording.md)。

## 工作范围

- 实现记录 ID、字节区间、多对多来源关联、分页/关联查询，保留无法解析的数据。
- 分别限制近期缓存、后台记录队列和磁盘保留量，后台批量写入，磁盘记录由用户开启。
- 实现正常历史过期与采集/记录丢失的独立提示、不可回溯标记及错误处理。
- 输出 CSV 概要和 JSONL 完整可用记录；内部保留存储实现可替换位置，不安装 Redis。

## 验收条件

- [ ] 一个块含多条消息、一条消息跨多块、一次操作多次读取尝试均可正确查询来源。
- [ ] 解析失败、未识别消息及发送进展仍可回溯，CAN 专用字段不进入通用 Message。
- [ ] 慢盘、磁盘失败或队列溢出不会无限增长内存或同步卡住通信；丢失计数和范围可见。
- [ ] 旧记录过期或写入丢失时引用返回明确状态，不能显示为完整记录。
- [ ] 导出保留范围、原始字节、元数据与关联；导出遇到轮换不静默省略来源。
- [ ] 记录模块不要求协议或 GUI 持有文件/Redis 连接，容量与批量参数可测量和调整。

## 验证证据

从写入、查询、导出 Interface 注入缓慢/失败后端，验证有界行为和证据完整性；性能结论由 08 的实际工作负载补充。
