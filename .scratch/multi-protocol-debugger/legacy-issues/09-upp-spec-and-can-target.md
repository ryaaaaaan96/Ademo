# 09 核对既定 UPP 规范与目标 CAN 支持组合

Status: needs-info
Stage: UPP/CAN 准备
Dependencies: 用户后续提供的 UPP 资料与目标 CAN 信息

## 目标

将固定 UPP 协议映射到公共契约，明确一组真实消息的验收数据，避免为了统一接口修改设备协议。依据：[ADR 0001](../../../docs/adr/0001-explicit-protocol-transport-support.md)、[接口契约](../interface-contracts.md)。

## 所需资料

- 规范版本、CAN ID 与设备寻址规则、标准/扩展帧及实际负载要求。
- 至少一组真实发送/接收样例及字段预期；校验、分片、时序、应答及主动上报规则以已有规范为准。
- 目标 CAN 适配器型号、驱动和连接条件；可用于验证的真实设备或可核验参考对端。

## 工作范围

- 整理消息、字段、设备身份、读写语义和支持组合，未知处明确标记，不发明协议。
- 核验 QCanBus 后端或所需传输 Adapter 对目标硬件的实际支持，形成安装与验证说明。
- 评估 COMMS 或其他实现是否适合已知格式；库的选择不能替代事务、路由和界面设计。
- 将真实样例转为实现 10 可使用的输入/输出验收数据，指出公共契约需要的真实能力缺口。

## 验收条件

- [ ] 字段、CAN 元数据、消息边界和预期结果均能追溯到规范或用户确认资料。
- [ ] 明确首个真实消息闭环的操作步骤、设备需求和判断依据。
- [ ] 列出目标硬件支持与限制，未验证的后端不标为已支持。
- [ ] 若公共契约有缺口，提出可审查的版本演进建议；不以协议名分支或修改 UPP 规避。
