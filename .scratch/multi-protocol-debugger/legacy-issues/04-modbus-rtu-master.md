# 04 实现 Modbus RTU 编解码、主站读写和轮询

Status: needs-triage
Stage: RTU
Dependencies: 01、02、03

## 目标

在单一串口会话中按总线调度多个设备，支持首版读取、写入和轮询，并完整关联请求、应答与读取重试。依据：[架构](../architecture.md)、[ADR 0007](../../../docs/adr/0007-session-read-retries-and-operator-recovery.md)。

## 工作范围

- 使用 01 选定路径，实现可供主从共享的 PDU、CRC 与 RTU 组帧/拆帧实现，覆盖功能码 `01/02/03/04/05/06/0F/10` 和异常响应。
- 采用协议计时和总线统一调度，处理分块输入、坏帧、超时及迟到数据；协议不自行创建串口。
- 支持单次读写、轮询和多个设备；操作验证、请求关联及结果归 Modbus 插件。
- 实现会话读取重试参数与简单断线恢复，设备写入和参数设置不自动重试。

## 验收条件

- [ ] 八个功能码的请求/响应和异常处理经规范样例或独立对端验证；错误长度、CRC 和地址不被误判成功。
- [ ] 一个 RTU 总线按协议约束调度在途事务，多设备不各自并发占用总线。
- [ ] 默认额外重试 2 次、超时 1000 ms、间隔 100 ms，次数不含首次；配置 0 可关闭重试，轮询周期独立。
- [ ] 写操作只自动提交一次；超时显示未确认，重连不补发，手动重发是新操作。
- [ ] 无应答广播若开放，按规范仅接受合法操作并显示本地完成，不伪造对端确认。
- [ ] 未识别或迟到输入可回溯，记录请求关联的限制，不用假定 RTU 存在事务 ID。

## 验证证据

通过可控时钟/传输输入验证超时与重试；独立参考实现或真实对端补充互通证据。实际时序与负载限制在 08 收束。
