# 08 验证 RTU 互通、时序与可支持负载

Status: needs-triage
Stage: RTU 验收
Dependencies: 03、04、05、06、07；实际或独立参考联调环境

## 目标

取得 RTU 第一阶段可交付的验证证据，为后续 UPP/CAN 提供稳定公共宿主，并用测量确定容量和性能范围。依据：[实施索引](../implementation-plan.md)、[缓存评估](../recording-cache-options.md)。

## 前置条件

记录设备/参考实现、串口适配器、端口拓扑、波特率及串口格式。同一物理总线只放一个主站；虚拟串口可验证逻辑，但不能替代实际硬件时间精度证据。缺联调资料时将本 issue 调整为 needs-info，不将推测写为测试结果。

## 工作范围

- 与独立主站/从站交叉验证八个功能码、多地址、异常、断线及恢复；不只进行本工具自测互通。
- 验证实际成帧时序、坏帧恢复、迟到响应、读取重试和写入不补发。
- 在记录开启/关闭、界面活跃、导出和人为慢盘时测量队列、处理耗时、内存、界面响应及记录吞吐/丢失。
- 依据证据选择默认容量与批量刷新参数，发布测试条件和限制，必要修复回到对应实现 issue。

## 验收条件

- [ ] RTU 主从的独立互通证据可复现，成功与未覆盖条件分别列出。
- [ ] 多会话不抢占同一端点，读取重试符合配置，写入不自动重发，停止和重连无旧操作污染。
- [ ] 记录过载下通信继续且丢失提示准确，内存保持在定义的上限策略内。
- [ ] JSON 即时替换、缺文件阻止启动、工作区恢复等实际使用路径通过。
- [ ] 给出可支持的已测条件、推荐初始容量和未验证上限，不只给未经测量的目标数字。
