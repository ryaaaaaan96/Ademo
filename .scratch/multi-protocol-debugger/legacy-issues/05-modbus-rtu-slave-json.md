# 05 实现 RTU 多从站模拟与外部 JSON 数据

Status: needs-triage
Stage: RTU
Dependencies: 02、03、04 的公共协议实现

## 目标

一个 RTU 从站会话提供多个设备的数据与应答，外部 JSON 是启动数据来源，运行中合法编辑和导入立即生效。依据：[接口契约](../interface-contracts.md)、[ADR 0008](../../../docs/adr/0008-external-slave-data-files.md)。

## 工作范围

- 每设备独立维护线圈、离散输入、保持寄存器和输入寄存器，主站观测缓存与模拟数据分开。
- 确定可扩展的单设备 JSON 格式、版本/字段校验及保存规则，提供有效和无效样例；地址从 0 开始，位数据为布尔值，寄存器为 16 位原值。
- 接入八个功能码及异常应答；启动前读取该会话全部必需文件。
- 导入先完整校验，再原子替换目标设备数据；保存和另存为处理一致快照与错误，不阻塞协议收发。

## 验收条件

- [ ] 任一必需 JSON 缺失、不可读或无效时该会话不启动，提示设备、路径与原因；其他会话可用。
- [ ] 合法改值、整份导入和地址范围调整在运行中对后续请求立即生效，一条请求不混用新旧数据。
- [ ] 失败导入保留原数据与文件绑定；未保存修改有保存、放弃或取消路径。
- [ ] 运行中外部文件修改/删除不热加载；下次启动重新读取，缺失不以零值或内嵌副本替代。
- [ ] 保存写回当前文件，另存为成功后按已记录规则更新绑定；保存失败不清除未保存状态或破坏已有文件。
- [ ] 远端主站只能按功能码访问对应数据区；本地模拟编辑与向真实设备写入分别处理。

## 验证证据

从数据管理和协议 Interface 验证 JSON 往返、坏文件、并发读写期间替换、保存期间再修改及多设备隔离；以独立主站验证标准应答。
