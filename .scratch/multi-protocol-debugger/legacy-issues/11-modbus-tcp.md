# 11 最后接入 TCP 通道与 Modbus TCP 主从

Status: needs-triage
Stage: TCP
Dependencies: 10；04/05 的 Modbus 公共实现

## 目标

按既定阶段顺序增加 Modbus TCP，复用协议数据与操作模型，验证不同连接语义可由相同宿主承载。依据：[架构](../architecture.md)、[接口契约](../interface-contracts.md)。

## 工作范围

- 通过传输插件提供 TCP 主动连接和监听端点，每个已接受连接有独立身份/代次及输入状态。
- Modbus 插件实现 TCP 承载、MBAP 组帧及事务关联，复用适用的 PDU、数据模型和视图。
- 主站一个远端 IP:port 一个会话，可有多个 Unit ID；不同远端分会话。从站一个监听端点提供多个模拟 Unit ID 和多客户端访问。
- 复用外部 JSON、读取重试、工作区、记录与简单恢复规则，不增加 TCP 专属主体分支。

## 验收条件

- [ ] TCP 分块/粘连、长度异常、连接关闭和迟到响应均正确处理，事务在连接及代次内关联。
- [ ] 主站多 Unit ID、服务端多客户端工作；同一模拟从站对各客户端提供一致数据，客户端解析状态互不混用。
- [ ] 主从八个功能码与异常响应通过独立对端验证，写入不重试、不跨重连补发。
- [ ] 端点冲突、后台记录与 JSON 失败遵循公共行为，RTU/UPP 功能不因接入 TCP 回归。
- [ ] TCP 实现开始前 10 的阶段验收完成；资料缺失时不擅自跳过 UPP/CAN 顺序。
