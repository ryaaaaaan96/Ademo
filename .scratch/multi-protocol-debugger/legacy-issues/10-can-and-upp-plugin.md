# 10 实现 CAN 传输与真实 UPP 协议插件

Status: needs-info
Stage: UPP/CAN
Dependencies: 08、09

## 目标

在 RTU 公共宿主上加载 CAN 和 UPP 插件，完成一组真实消息收发解析，验证自定义协议扩展。依据：[接口契约](../interface-contracts.md)及 09 核实后的协议资料。

## 工作范围

- 接入目标 CAN 后端，保留 ID、帧格式、时间及后端实际支持的状态；声明硬件能力和支持组合。
- UPP 插件自行组包、解释元数据、处理已有交互规则并发布结构化消息，不直接创建 CAN 设备。
- 使用统一记录、操作与视图挂载；UPP 专用字段不被强制转成寄存器，也不进入通用 Message 的 CAN 专属成员。
- 若规范确有分片或特殊时序，按 09 的证据实现；不存在的规则不预先添加。

## 验收条件

- [ ] 在目标硬件/参考对端完成真实消息闭环，与 09 的字节和字段预期一致。
- [ ] 新协议与传输的正常接入不修改主体协议分支；记录任何实际 SDK 演进及理由。
- [ ] 未识别和错误输入可回溯，来源关联保留必要 CAN 元数据。
- [ ] 后端接受发送不显示为设备已执行；未知操作不擅自自动重试，设备写入遵循不重试策略。
- [ ] 与 RTU 会话同时运行保持端点和状态隔离，过载策略一致。
