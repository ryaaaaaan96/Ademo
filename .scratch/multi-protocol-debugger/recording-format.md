# 有界磁盘记录与归档格式

对应当前 [12](issues/12-bounded-disk-recording.md)。记录由操作人员主动开启；近期缓存、待写队列和磁盘留存分别配置，不使用 Redis。所有文件等待在后台执行，协议输入继续先获得原始记录身份再解析，磁盘队列满不能阻止通信。

## 容量与生命周期

- 默认近期缓存沿用 11：原始/消息/操作 256/256/128；每操作观察引用最多 512，省略数量单独保留。
- 默认待写队列 1024 项、8 MiB，以序列化后的真实字节数执行双限额；可设 1..8192 项、1 KiB..32 MiB。后台每批默认 64 项，可设 1..256。
- 内存中最多一个待写队列、一个已取出的批次和当前准备提交的事件。批次不超过队列原有字节预算；在途批次不计入待写队列计数，队列锁只保护内存，不跨文件等待。单事件最多 128 KiB；超过事件、分段或队列预算时计为丢失。
- 默认磁盘保留 64 MiB，每分段 1 MiB；总容量可设 256 KiB..512 MiB，分段 1 KiB..8 MiB 且不超过数据预算的一半。最多 64 个分段。总预算预留 128 KiB 给索引、原子替换临时文件和锁；其余为分段数据。
- 容量约束针对该目录中本模块管理的文件。用户导出的 CSV/JSONL 和无关文件不由记录器删除，也不属于自动留存预算。建议为记录单独选择目录。
- 同一目录由 QLockFile 独占，最多同时运行四个记录器。另一个会话可使用另一目录；目录冲突或文件错误只禁用磁盘记录，不停止会话。
- 初始化失败会排空已接纳事件、保留独立丢失统计并自动释放后台容量；错误对象可以继续显示诊断，不占用等待工作的线程。
- `stopRecording()` 异步排空并关闭文件、释放目录锁后返回完成结果；停止通信不隐式结束磁盘记录。会话销毁会请求后台排空，不在通信上下文等待磁盘。

## 身份与文件

`DebugSession.sessionId()` 为该会话对象的 UUID。每次开启记录另有 `recordingId` UUID；原始、消息和操作 ID 仍为会话内稳定整数，跨启停不复用。归档查询必须明确选择会话 UUID，不能将不同进程中同为 1 的操作 ID 合并。

目录包含 `manifest.json` 和 `segment-<20位递增编号>-<recordingId>.jsonl`。索引和事件均为 schemaVersion 1；64 位 ID、计数、字节预算、单调时钟采用十进制字符串。索引使用 QSaveFile 原子替换，数据分段在后台按批写入、flush，并在切段时检查 flush 结果。

事件类型：

| type | 内容 |
| --- | --- |
| session | 会话 UUID、协议/传输身份、角色、端点、协议配置和宿主 recovery 策略 |
| trace | 原始字节、运行代次、时间、实际元数据、线路静默元数据及观察该记录的操作 ID |
| message | 解析状态、字段、操作关联、来源 ID 与精确 offset/length |
| operation | 请求参数、最新状态、发送/本地完成事实、localOnly、观察引用和省略数量 |

每个事件带 sessionId、recordingId、sequence 和 eventUtc。RX 与发送尝试元数据在入队前已完整组装，不使用先入队后补字段的副本。操作创建、进展、终态及停止取消均记录；文件本地操作的 localOnly 与 working 等状态保留。

启动、协议配置发布和恢复策略变化会追加会话配置事件，因此先开启记录再启动也能保存实际配置。断线经宿主恢复路径直接结束的通信操作也持久化为 transport-error，已提交而未确认时保留 uncertain。查询和导出中的 sessionConfiguration 是该归档可用范围内最后一份会话配置快照，不宣称为所有历史操作发生时的配置。

## 丢失、轮换与恢复

待写队列溢出、超大事件、文件写入失败会产生记录事件丢失。计数和首末 UTC 在队列外独立维护；即使队列已满，丢失提示也不需要再次入队。统计的单位为归档事件，包含原始、消息、操作和会话事件，并非物理帧数量。

索引保留整个归档目录的累计丢失计数/时间、正常轮换计数/时间，以及最多 64 个精确连续原始 ID 丢失区间、32 个轮换区间。区间历史超限时保留累计计数和时间，并设置截断标记；无法证明原因的缺失来源显示 unavailable，不猜成完整证据。正常轮换与过载丢失分别报告。

异常退出后发现未进入索引的孤儿分段，保守纳入容量并设置 archiveGap。未知身份或时间的孤儿分段被轮换时，不捏造精确轮换区间。外部删除/改写、损坏、部分最后一行、分段数量或行数不符、查询时被轮换均形成不完整提示。索引的必需字符串整数、容量、时间、UUID、布尔值和范围会严格校验；坏索引拒绝加载和写入，保留原文件。

## 查询与导出

`queryArchive(directory, sessionId, filter)` 在独立后台池运行，最多两个并发查询。首先读取消息/操作，再按关联解析来源；范围选择补齐可用来源。结果最多保留原始/消息 8192 项和操作 1024 项，序列化规模分别限制为 32/8/8 MiB；达到预算时明确记录 queryOmittedEntries。每轮扫描最多 512 MiB，单行最多 128 KiB。

归档与实时查询共用 filterSnapshot 的关联语义：某条消息可在另一个未完成操作的观察窗口中被查到，但其 operationId 仍保持协议已确认的实际归属；不会因观察关联而篡改所属操作。预算不足时显式省略计数，不能提前按消息所属操作过滤后再声称完整。

来源状态为 available、expired、lost、unavailable 或 invalid-range；只有 available 提供实际字节。retention 摘要的 scope 为 archive-directory，累计计数覆盖该目录的全部会话；complete 表达整个归档范围是否可证明完整，不能推断目录里曾经出现过的所有数据都还可用。

历史结果是独立值快照，复用 11 的后台 CSV/JSONL 导出和最多四项导出限额。JSONL 包含会话身份、retention 摘要、实际可用原始字节/元数据、消息/操作及缺失来源；CSV 保留概要与来源状态。查询期间发生轮换会明确标记；捕获后的快照不受之后淘汰影响。实际磁盘或进程被强制终止时不保证导出完成，只有文件提交成功才报告完成。
