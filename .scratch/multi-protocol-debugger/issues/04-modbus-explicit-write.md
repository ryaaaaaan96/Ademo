# 04：执行不会自动重试的设备写入

Status: ready-for-agent
Stage: RTU
Blocked by: [02 完成一次 RTU 保持寄存器读取](02-rtu-first-register-read.md)

## What to build

操作人员执行单个/多个线圈与保持寄存器写入，查看应答或结果不确定提示，并自行决定是否再次操作。

本项交付可验收的完整流程，包含必要界面、数据与协议/传输协作和测试。规格用户故事：11、14、18、19、21、47。

## 依据与边界

依据：[正式规格](../spec.md)、[领域术语](../../../GLOSSARY.md)、[架构基线](../architecture.md)、[接口契约](../interface-contracts.md)。当前编号以 [实施索引](../implementation-plan.md) 为准。

- 沿用已验证的 Windows x64、Qt 6.12.0 LLVM-MinGW、Clang 22.1.7、C++17、CMake 3.30.5、Ninja 1.12.1 和 VS Code，见 [环境证据](../toolchain-environment.md)。已有验证不重复列为待办；正式产品与插件仍需本项相关验证。
- 主体管理会话/通道/记录，协议负责协议交互及专用界面；只扩展本流程必要能力。一会话一个端点、一种协议，可有多个设备；设备写入不自动重试。
- UI 采用 Widgets；测试 Adapter 不列为真实支持组合。未进入本项的后续能力保持在对应 ticket，不把本项扩成完整框架。

## 验收条件

- [x] 覆盖 05、06、0F、10 的操作入口、请求、正常应答与异常响应。
- [x] 超时及传输失败不自动重试；本地发送完成不等于设备确认，手动重复形成新的操作及记录关联。

- [x] 通过调试会话公开接口验证本项外部行为，附必要界面流程证据；记录实际执行的测试、环境与未覆盖条件。

## 验证方式

以调试会话的启动/停止、操作提交、数据导入/修改及公开查询为主要入口，观察结果、发送数据和回溯证据，底层按需注入可控传输与时钟。仅在契约不能通过该入口验证时补充插件加载或界面边界验证；不测试私有容器和辅助函数调用顺序。真实串口/CAN 与独立对端的证据和模拟测试分开记录。

在独立 worktree `rtu-slave` / 分支 `codex/rtu-slave`，基于共享基线 `abb5169` 复用 01/02 实施。四种写入动作均通过插件视图与公共通道执行，验证回显值/起址/数量、CRC、Unit 与功能码后才视为设备确认。已提交未确认的写入不自动重试；停止/重启不补发，人工再次执行生成新操作与来源记录。

Debug、Release 均通过 3/3 CTest；生命周期 13、读取 36、写入 36，共每配置 85 项 Qt Test 检查（含初始化/清理），0 failed / 0 skipped。会话公开接口覆盖规范向量、四种异常、越界、超时、本地失败、断线、停止、手动重做、无重试及来源关联；原生 Widgets 覆盖四动作成功及异常/超时/断线/停止的不确定提示。详见 [04 验收证据](../evidence/04/acceptance.md)。真实串口成功写入与独立硬件对端尚未验证，留待 13。

### 2026-10-23：停止未确认写入的公开终态修复

集成审查发现宿主先finished再protocol.stop，导致协议发布的cancelled/uncertain被忽略。现协议先发布终态，宿主仅兜底剩余未完成操作，已提交未确认时明确标记uncertain；保留08的后台localOnly操作及preparing保护。新增公开回归覆盖停止时等待本地完成/设备确认、排队未发送、重启不补发，以及宿主fallback与归档JSONL。定向Debug 5/5 CTest、98项通过，0失败/跳过；最终集成双配置另由根代理验证。详见[停止终态修复证据](../evidence/stop-uncertain-reviewfix/acceptance.md)。
