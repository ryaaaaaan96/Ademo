# 07：RTU 从站接受设备写入并反馈数据变化

Status: ready-for-agent
Stage: RTU
Blocked by: [04 执行不会自动重试的设备写入](04-modbus-explicit-write.md)、[06 从外部 JSON 启动多设备 RTU 从站并读取](06-rtu-slave-json-read.md)

## What to build

外部主站写入模拟设备后，界面和后续读取均反映同一份更新后的数据。

本项交付可验收的完整流程，包含必要界面、数据与协议/传输协作和测试。规格用户故事：11、23、24、34。

## 依据与边界

依据：[正式规格](../spec.md)、[领域术语](../../../GLOSSARY.md)、[架构基线](../architecture.md)、[接口契约](../interface-contracts.md)。当前编号以 [实施索引](../implementation-plan.md) 为准。

- 沿用已验证的 Windows x64、Qt 6.12.0 LLVM-MinGW、Clang 22.1.7、C++17、CMake 3.30.5、Ninja 1.12.1 和 VS Code，见 [环境证据](../toolchain-environment.md)。已有验证不重复列为待办；正式产品与插件仍需本项相关验证。
- 主体管理会话/通道/记录，协议负责协议交互及专用界面；只扩展本流程必要能力。一会话一个端点、一种协议，可有多个设备；设备写入不自动重试。
- UI 采用 Widgets；测试 Adapter 不列为真实支持组合。未进入本项的后续能力保持在对应 ticket，不把本项扩成完整框架。

## 验收条件

- [x] 补齐从站 05、06、0F、10 与异常响应，复用已验证的公共写入 PDU 语义。
- [x] 每条请求采用一致数据视图，不跨设备写入；多个值的合法写入按协议完成后再应答。

- [x] 通过调试会话公开接口验证本项外部行为，附必要界面流程证据；记录实际执行的测试、环境与未覆盖条件。

## 验证方式

以调试会话的启动/停止、操作提交、数据导入/修改及公开查询为主要入口，观察结果、发送数据和回溯证据，底层按需注入可控传输与时钟。仅在契约不能通过该入口验证时补充插件加载或界面边界验证；不测试私有容器和辅助函数调用顺序。真实串口/CAN 与独立对端的证据和模拟测试分开记录。

### 2026-10-22：07 实施验收

独立 worktree/分支 `rtu-slave` / `codex/rtu-slave`，以前置共享基线 `e0d3ce8` 实施。四种写入共用 04 的 PDU 语义，完整校验后一次更新目标设备，再应答；每次成功更新 dirty/revision，界面及后续读取反映同份数据。广播写入逐设备校验且不应答；错误、不匹配设备及 pending 时的新请求不会部分改值。应答失败不撤回已执行写入，不自动重发或保存文件。

Debug、Release 均通过 6/6 CTest，各 156 项 Qt Test 检查、0 failed / 0 skipped；本项从站写入套件 25 项，含正常/异常、单播隔离、广播、整体更新、最大合法数量、来源关联、发送失败与原生 UI。详细日志、截图、SHA-256、过程修复和环境限制见 [07 验收证据](../evidence/07/acceptance.md)。真实硬件留待 13；08 运行编辑和未保存保护不在本项。Status 保留分诊标签。
