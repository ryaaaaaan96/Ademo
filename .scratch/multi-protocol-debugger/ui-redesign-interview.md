## 已确认：第一轮

### Q1：核心数据界面

用户原文：“核心数据界面按照参考项目来，没有名称就显示modbus寄存器地址，列不必完全参考参考项目，可以增加一些显示的内容”。

采用参考项目的参数表方向；无名称时以 Modbus 寄存器地址作为显示标识。列可根据调试需要调整，尚未冻结列集合、编辑交互、值类型及分组规则。不把先前建议的两个独立数据视图视为已采纳。

### Q2：导航

用户采纳“左侧会话→设备、中央所选设备的数据与操作、底部可展开通信记录”的布局。连接参数进入独立配置入口，运行时保留简明状态和必要控制；切换选择不停止其他会话通信。

### Q3：编辑能力归属

用户原文：“不采纳建议，新协议的编辑也由插件来实现”。

协议相关编辑能力由插件承担，不采纳由主体统一实现参数定义编辑的方向。具体可编辑内容与编辑结果仍待明确；不能据此推定已要求实现通用协议编辑器或代码生成器。

此前规格 Out of Scope 排除了用户协议编辑器，本轮表述需要进一步明确范围后再修订。ADR 0004 的协议专用能力归插件边界仍可作为设计基础；暂不修改原文。

### Q4：曲线原型

采纳将“选择参数→打开曲线→观察变化”纳入可操作原型。完整绘图功能的正式实施范围尚未确定；保留 Qt Widgets 方向。

## 第二轮：用户反馈与范围

### Q5：插件定义展示，框架提供模板

用户原文：“按照参考来，每个协议显示哪些内容可以有插件来定义吗，当前的就先以这个值来进行配置方式来显示可以吗，作为通用模板供每个插件调用”。

方向为框架提供可复用的参数表模板，协议插件决定展示内容，允许插件复用。模板以参考项目为起点，不把上一轮提出的列集合、独立待写值列视为已经采纳。“值”列的具体编辑与回读行为下一轮核对。

### Q6：JSON 分组

用户原文：“这个分组应该是json来实现呀，如果插件要求有分组就全部显示在一个组”。

分组由 JSON 描述，解释归插件。后半句是否指“不需要分组时全部放在默认组”尚待确认，不替用户改写为已确定规则。之前建议的无定义文件地址范围添加流程未被确认。

### Q7：文件编辑独立入口

用户原文：“文件保存和设置分开来，文件编辑有一个单独按钮，进入文件编辑界面，这部分可以参考参考项目”。

参数操作与文件编辑分离。文件编辑有独立按钮与页面，参考项目相应页面；文件保存与设备设置为不同动作。文件编辑范围、保存后是否更新当前运行配置，以及从站模拟值的编辑入口尚需明确，不能把之前的整套主从操作建议视为已采纳。

### Q8：主体基础能力与插件专用编辑

用户确认：“是的，框架提供基础能力”。

各插件决定可编辑内容，并提供自己的编辑页面；主体提供承载入口与基础能力，不要求所有插件具有同一种编辑器。插件可以在其支持范围内编辑参数或命令/报文结构，UPP 仍须遵守既定规范。此项是能力边界，不表示本轮已经要求实现所有编辑器。

## 已确认：第三轮

### Q9：分组缺省规则

JSON 定义了分组就按组显示，不需要分组时所有参数显示在一个默认组。插件解释 JSON 并提供分组，主体不写死名称和协议规则。此项明确第二轮 Q6 的歧义。

### Q10：单值列与待提交状态

采用参考式单“值”列：平时显示读回结果，双击编辑，点击本行“设置”才提交设备写入。待提交内容有明显标记；编辑期间轮询不能覆盖输入。写入失败或结果不确定时显示对应状态，不把输入值当作已确认的设备数据。此项明确第二轮 Q5 中值列交互。

### Q11：保存与应用分开

文件编辑页保存仅更新文件，不发送设备设置，也不静默替换运行数据。用户通过明确的“加载／应用”动作更新当前会话使用的内容。从站操作页修改模拟值仍立即生效；文件编辑页的修改经过加载后才影响运行数据。

用户确认的是保存和应用两类动作分开，尚未冻结 JSON 文件组织和字段。沿用此前从站启动校验外部文件、缺失不启动、运行期间不热加载的约定。

## 第四轮：多窗口与曲线方向

### Q12：多个协议调试窗口

用户原文：“多个协议的窗口做成可浮动窗口，一个界面可以显示多个窗口”。

采用可同时展示的多个协议调试窗口，不再限定为中央仅展示一个选中设备页面。保留此前会话与设备导航作为待整合的入口。窗口对应会话还是设备，以及浮动是否包括脱离主窗口，下一轮明确。

此回答没有确认此前 Q12 关于新建会话、添加设备、无 JSON 生成地址表的完整建议；这些流程仍待确认。

### Q13：保留读取与轮询操作

用户答复“保留”。保留表格上方的读取选中项、读取当前组、开始／停止轮询以及行内单项读取与设置。轮询明确范围和周期，切换视图不停止通信；写入由用户主动触发，不随轮询执行。

### Q14：QWidget 内嵌 QML 曲线

用户原文：“支持，然后这个界面可以做成用widget内嵌QML的方案，这样画图”。

支持从参数行打开曲线，并在同一曲线窗口加入同一设备的多个数值参数；原型包含图例、暂停显示、清空、缩放。打开曲线观察已有数据更新，需要采集时显式开启轮询。

曲线界面采用 QWidget 内嵌 QML，其他工作台和表格继续采用 Widgets。此选择与 ADR 0006 的技术边界一致；绘图正式交付范围仍在原型确认后写入规格和任务。

### Q15：通信记录跟随调试窗口

用户原文：“底部通讯记录随浮动串口移动”。

按上下文理解为通信记录位于所属浮动调试窗口底部，随该窗口一起移动，不使用随全局选择切换的唯一底部记录区。窗口与会话对应关系确定后明确其记录范围，不能因此丢弃无法解析的原始报文。

## 已确认：第五轮

### Q16：窗口与会话对应

一个调试窗口对应一个调试会话，管理该会话下的多个设备；同一协议可有多个不同会话窗口。每个窗口包含设备选择、参数分组、操作区和该会话的通信记录。此项明确 Q12 的窗口粒度与 Q15 的记录归属。

### Q17：停靠与浮动

支持主界面内并排排列，也支持拖出成为独立窗口并放回主界面；可放到另一显示器。提供平铺与恢复布局入口，工作区保存位置、大小及停靠状态。

### Q18：关闭与通信生命周期

关闭调试窗口停止对应会话通信，保留工作区中的配置以便再次打开；有未保存内容时提示处理。最小化、折叠、移动窗口不停止通信。

## 已确认：第六轮

### Q19：新建入口

新建会话时选择协议、角色并配置端点，随后在调试窗口内添加设备，加载参数 JSON 或通过插件编辑页面新建配置。Modbus 主站可按数据区、起始地址和数量生成参数行，无名称时显示地址；从站仍须有有效数据文件才能启动。

### Q20：文件编辑页面

每个调试窗口提供“参数操作／文件编辑”两页，通过独立入口切换。文件编辑页明确显示设备和文件路径，提供保存、另存为、加载／应用；保存不影响通信数据，应用校验后更新明确指定的设备。切换页面不影响其他会话。

## 原型验证阶段

Q1–Q20 已明确首版原型所需的界面方向。使用独立 Qt Widgets 原型验证，多窗口可停靠或浮动，曲线区域实际使用 QQuickWidget 内嵌 QML；模拟数据用于界面交互，不接真实串口或 CAN，不编造 UPP 协议。原型代码位于本目录 `ui-prototype/`，不修改产品实现。
